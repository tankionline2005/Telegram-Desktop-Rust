# Чем клиент лучше оригинала

Список того, в чём порт уже превосходит Telegram Desktop. Сюда попадает только то, что
проверено: замером, тестом или воспроизведением в обоих клиентах. Подробности
оптимизаций — в [OPTIMIZATIONS.md](OPTIMIZATIONS.md), решения — в журнале
[ARCHITECTURE.md](ARCHITECTURE.md).

## Надёжность

| Что | В tdesktop | У нас | Как проверено |
|---|---|---|---|
| Черновик не пропадает | Если открыть чат на телефоне, до которого синхронизация черновика ещё не дошла, телефон присылает пустой черновик (`draftMessageEmpty`), и текст, набранный на компьютере, стирается — из поля ввода и из черновиков. Баг существует годами и воспроизводится стабильно | Пустой черновик с сервера не трогает локальный. Черновик очищается, только когда с другого устройства приходит исходящее сообщение с тем же текстом (его отправили оттуда) | Воспроизведено пользователем в tdesktop (текст пропал) и у нас (остался); тесты `tdesktop_wipes_the_draft_on_an_empty_cloud_draft` и `fix_keeps_the_draft_on_an_empty_cloud_draft` в `crates/data/src/drafts.rs` |
| Сессия не портится при сбое | — | Файл сессии и положение окна записываются атомарно (временный файл + переименование): падение в любой момент оставляет целый файл | Тест `write_atomic_replaces_and_leaves_no_temp`; до исправления падение во время записи оставило пустой `session.bin` |
| Чаты вне списка сервера не пропадают | Некоторые чаты сервер не отдаёт в списке чатов (`messages.getDialogs`), хотя они существуют (`messages.getPeerDialogs` их знает). Такой чат появляется в списке, только пока в этом запуске открыт его диалог: после перезапуска он исчезает | Открытый чат сохраняется в кэше с пометкой «сервер его не перечисляет» и остаётся в списке на своём месте по дате. Пометка снимается, если сервер начнёт его перечислять; чат удаляется, если сервер перестанет отдавать его диалог | На аккаунте пользователя: после перехода к оригиналу и двух «перезапусков» с полной сверкой списка чат на месте (`tdr probe keep/relist`); тест `pinned_order_and_pruning` |

## Скорость

| Что | В tdesktop | У нас | Как проверено |
|---|---|---|---|
| Список чатов при запуске | Не хранится между запусками: ждёт `messages.getDialogs` (≈ 0,9 с на 200 чатов) | Из кэша на SQLite, потом догоняется разницей обновлений | 20 чатов из кэша — 5,4 мс (C6) |
| Первый ответ сервера после запуска | Новый временный ключ (DH) при каждом запуске: ≈ 1,2 с | Временный ключ и соль сохраняются: ≈ 0,12–0,17 с | Замер (C3, C4) |
| Первый запрос к «медийному» DC | Ключ и авторизация создаются при первой загрузке файла: ≈ 1,1 с | Соединение готовится в фоне: ≈ 0,14 с | Замер (C5) |
| Аватары при запуске | Догружаются по мере показа строк | Из файлового кэша на отдельном потоке, не дожидаясь синхронизации с сервером: первый — через 0,47 с после запуска, синхронизация заканчивается через 0,86 с | Журнал запуска на аккаунте пользователя |
| Проверка DH | Две проверки простоты 2048-битных чисел на каждое рукопожатие | Для известного безопасного простого — только проверка генератора | Тест (C1); заодно закрыта лазейка с `g = 5` (C2) |
